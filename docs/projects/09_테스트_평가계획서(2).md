# 09. 테스트·평가계획서

> **이 문서는 무엇인가:** 일반 기능과 AI 실험의 시험 방법, 시험 데이터, 합격·실패 조건을 정한다.  
> **언제 읽는가:** 테스트를 쓰기 전, AI 비교실험을 실행하기 전, 통합 확인일과 최종 완료 판정 때 읽는다.  
> **완료 원칙:** 코드가 있다는 사실이 아니라 같은 명령으로 다시 실행 가능한 결과와 오류 분석이 있어야 완료다.

## 1. 목적

완료를 코드 존재가 아니라 재현 가능한 실행 증거로 판정한다. 기능 테스트와 AI 실험은 같은 CI/CD Gate에 연결하되, 실제 데이터 결과는 비공개 Artifact에 저장하고 공개 포트폴리오에는 Synthetic 재현셋과 집계 Metric만 포함한다.

## 3. 시험 데이터 전략

### 데이터 묶음

- `fixture_unit`: 최소·경계·invalid record
- `demo_scenarios`: 공개 가능한 6개 Event 흐름
- `golden_nlu`: intent/entity/risk 정답
- `golden_retrieval`: query→graded relevant source
- `golden_graph`: query→entity/path/answer
- `agent_scenarios`: state, injected failure, expected transition/tool
- `private_business_validation`: 비식별 실제 데이터, 접근 제한

Split은 customer/thread/time group 기준이며 manifest hash와 dataset version을 고정한다. Synthetic generator가 Test 정답이나 source example을 보지 않도록 분리한다.

## 5. AI 평가

### 5.1 프롬프트·자연어 이해

| Metric | 정의 | 보고 방식 |
|---|---|---|
| Intent Macro/Micro F1 | class별/전체 | class support/confusion 포함 |
| Entity F1 | span 또는 normalized entity | entity type별 |
| JSON Valid Rate | schema pass / total | retry 전/후 분리 |
| Exact Match | 전체 object 정확 일치 | strict |
| Field Accuracy | required field별 | missing/wrong/extra |
| Calibration | confidence vs correctness | ECE/reliability bins |
| Latency/Cost | p50/p95, input/output token | route/model별 |

`PROMPT-01`: zero-shot, structured zero-shot, few-shot, self-check variant를 동일 set/seed/model에서 비교한다. `FT-01~05`: Base, QLoRA checkpoint, Large API를 동일 Test에 실행한다.

### 5.2 검색

| Metric | 정의 |
|---|---|
| Recall@K | relevant source 중 top-K 회수 비율 |
| Precision@K | top-K 중 relevant 비율 |
| MRR | 첫 relevant의 reciprocal rank 평균 |
| nDCG@K | graded relevance 순위 품질 |
| Duplicate Rate | context 내 near duplicate 비율 |
| Citation Precision/Coverage | 인용이 claim을 지지/필요 claim이 인용됨 |
| Groundedness | evidence 밖 주장 비율의 역개념 |

BM25/Vector/Hybrid/Hybrid+Reranker는 동일 corpus snapshot, metadata filter, Golden Set으로 비교한다. Product exact/typo/alias/compatibility/component/live inventory/policy/no-answer slice를 별도 보고한다.

### 5.3 QLoRA 미세조정

- checkpoint마다 NLU Metric, train/val gap, per-class confusion
- Base/QLoRA/Large API의 동일 hardware 조건 latency(불가하면 환경 명시)
- adapter rank/LR/step과 artifact hash
- overfit: near duplicate 제거 전후, rare class, brand memorization
- 채택은 `04_AI_ML_기술_및_실험_설계서.md`의 채택 규칙을 적용

### 5.4 그래프

- entity resolution accuracy
- relation/path Recall@K
- multi-hop answer accuracy
- SQL/Hybrid/Graph/Graph+Vector latency와 query complexity
- simple query와 multi-hop query를 섞어 Graph가 불필요한 영역을 식별

### 5.5 대화 메모리

- entity carryover F1
- contradiction/wrong-memory rate
- total input token/thread
- task completion
- summary drift
- full transcript vs recent+summary vs relevant-history 비교

### 5.6 에이전트

- state transition accuracy
- workflow completion/recovery rate
- duplicate tool/side effect count(필수 0)
- retry count, timeout recovery time
- correct HITL/safety route
- node/model call/token/cost
- checkpoint resume 전후 repeated work

### 5.7 모델 선택기

Large-only와 Router를 같은 scenario workload로 replay한다.

- quality/safety metric
- cost/request와 총 비용
- avg/p95 token
- p50/p95 latency
- cache hit/stale hit
- large model call rate
- human fallback rate

비용 절감이 있어도 critical quality/safety regression이면 채택하지 않는다.

## 6. 통계 처리 원칙

- seed와 run 수를 기록하고 가능한 실험은 bootstrap confidence interval 제공
- query/thread 단위 paired comparison
- 평균뿐 아니라 median/p95와 critical slice
- Test Set을 반복 튜닝에 사용하지 않고 Validation으로 결정 후 Test 1회 확정
- 데이터가 작으면 유의성 과장을 피하고 effect size와 error sample을 함께 제시

## 7. 통합 확인일

통합 확인일에는 직전까지 실제 구현되고 계약이 확정된 Interface만 연결한다. 세 트랙 전체를 하나의 흐름으로 강제하지 않으며, 계약 불일치를 임시 필드·가짜 Projection·타입 단언으로 숨기지 않는다. 연결 가능한 구간은 PASS, 계약 때문에 막힌 구간은 `PARTIAL/BLOCKED`로 분리하고 Finding ID·owner·재검수 Day를 기록한다.

## 9. 완료 증거 기준

각 완료 항목은 다음을 연결한다.

```text

expected vs actual
```

민감 Artifact는 비공개 path/hash만 기록한다. 공개 Artifact는 Synthetic으로 재현 가능해야 한다.

## 11. 실제 사업자 비공개 검증

Core Build에서는 안전한 Read와 화면/제안 검증만 한다. 사업자는 다음을 평가한다.

- 예약 위험/Task가 실제로 유용한가
- 오늘의 우선순위가 운영 판단과 일치하는가
- 예상 재고/Mapping이 수동 결과와 얼마나 일치하는가(Shadow Roadmap)
- 알림량과 false positive가 감당 가능한가
- AI Draft/설명의 근거가 신뢰 가능한가

Feedback은 단순 만족도가 아니라 scenario ID, decision, correction, reason으로 수집해 다음 evaluation set 후보로 관리한다.
