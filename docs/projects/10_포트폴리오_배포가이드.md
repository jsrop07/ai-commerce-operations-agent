# 10. 포트폴리오·배포가이드

> **이 문서는 무엇인가:** 실제 사업 데이터를 공개하지 않고도 동일한 기능과 AI 실험 깊이를 보여주는 데모·배포 방법을 정한다.  
> **언제 읽는가:** Day 17부터 공개 자료, 데모 데이터, 배포 환경, 시연 순서를 만들 때 읽는다.  
> **핵심 원칙:** 공개 포트폴리오는 별도 Demo Tenant·Demo DB·합성 데이터만 사용하며 실제 사업자 데이터와 자격증명을 포함하지 않는다.

## 1. 공개 전략

공개 포트폴리오는 실제 쇼핑몰의 복제본이 아니다. **동일한 Backend/AI Contract와 Pipeline을 사용하는 별도 Demo Tenant**다. 실제 사업자명·매출·주문·상품 원문·고객정보·Credential은 공개하지 않는다.

## 3. 환경 분리

| Resource | Demo | Production/Pilot |
|---|---|---|
| Tenant | `demo_store` | private tenant ID |
| DB | synthetic only | protected operational DB |
| Vector/Search | demo corpus | sanitized private index |
| Queue/Cache | demo namespace/instance | separate instance |
| Object Storage | public artifacts | restricted bucket |
| Credential | DemoProvider/test model key | read-only provider secret |
| Domain | public demo | private/VPN/admin |
| Telemetry | sanitized | restricted, PII masking |

배포 파이프라인은 Demo artifact를 Production에 promote하지 않고 같은 source commit을 환경별 build한다.

## 4. 데모용 합성 데이터

Synthetic board-game store는 다음을 포함한다.

- Product 50~100, SKU/option, Brand/Category/Language
- BaseGame/Expansion/Component/Compatibility relation
- 60~90일 online/offline sales와 stock snapshot
- standard/reservation orders, incoming stock, return/cancel records
- launch events와 task templates/dependencies
- 문의 intent별 대표·경계·근거부족 사례
- deliberate anomaly: duplicate event, ambiguous mapping, shortage, delay, inquiry/return spike

실제 레코드를 단순 치환해 공개하지 않는다. Synthetic generator와 seed를 제공해 재생성 가능하게 한다.

## 5. 데모 이벤트 시나리오

### 시나리오 A — 오프라인 판매와 재고 위험

1. SKU 재고 3 표시
2. Offline sale 2 발생
3. duplicate toggle로 동일 Event 재전송
4. expected stock 1, dedupe count, risk Task 확인
5. Production write call=0 Trace 확인

### 시나리오 B — 예약주문 누락 방지

1. 예약 5, available 1, incoming 2
2. 부족 2 계산과 Aging Task
3. incoming delay 발생
4. 배송 영향 주문과 priority 상승 확인

### 시나리오 C — 출시 지연 재계획

1. Flow A launch 생성
2. Task dependency 확인
3. incoming +3일 delay
4. impacted Task와 proposed diff
5. 승인 전 원 일정 불변 확인

### 시나리오 D — 근거 있는 고객문의 답변

1. “확장팩만으로 플레이 가능한가?” 문의
2. intent/entity와 relation retrieval
3. citation Draft
4. 근거 제거 variant에서 abstain 확인

### 시나리오 E — 위험 행동 차단

환불/가격/재고 Write를 유도하고 Policy Denied, Audit, provider call 0을 보여준다.

### 시나리오 F — AI 비교실험

Retrieval 또는 Model Router 비교 화면/리포트에서 Baseline과 채택 결정을 보여준다.

## 6. 배포 구성

### 최소 공개 데모 구성

- Web: static/SSR frontend
- API: containerized FastAPI
- Worker: background queue consumer
- PostgreSQL+pgvector
- Redis(optional degrade 가능)
- Object storage for public experiment reports
- Small model은 외부 endpoint 또는 사전 배포된 inference; budget/timeout 필수

### 자동 배포 전 확인 조건

1. lint/type/unit
2. OpenAPI/JSON Schema contract
3. synthetic integration/E2E
4. secret and PII scan
5. dependency/container scan
6. migration dry run
7. Demo deploy
8. smoke + safety denial
9. manual release promotion

Production 배포는 별도 workflow와 approver를 사용한다.

## 7. 환경설정

- `.env.example`에는 key 이름과 Demo 기본값만
- provider/model endpoint와 secret은 secret manager
- `ENVIRONMENT`, `TENANT_ID`, `WRITE_MODE`, `GLOBAL_WRITE_KILL`, `MODEL_BUDGET`, `DATASET_VERSION`
- 안전 default: `WRITE_MODE=disabled`, `GLOBAL_WRITE_KILL=true`
- unknown/missing env는 startup fail 또는 read-only degrade

## 8. 공개 설명서 구성

1. 한 줄 문제와 실제 Pain Point
2. 90초 Demo GIF/video
3. Architecture와 Safety Boundary
4. 3개 핵심 Scenario
5. AI Engineering Experiment Table
6. Metric과 Error Analysis(실제 수치만)
7. Model Routing cost benchmark
8. Local Demo 실행법
9. Synthetic Data 설명
10. 제한/채택하지 않은 기법
11. 21일 이후 시범운영 추진계획

“QLoRA/RAG/Graph 사용” 대신 `가설→baseline→metric→결정`을 첫 화면에서 보여준다.

## 9. 포트폴리오 증거 묶음

| Artifact | 내용 |
|---|---|
| Architecture | read/write trust boundary, AI Backend |
| Experiment Report | prompt, retrieval, QLoRA, graph, memory, agent, router |
| Error Analysis | representative failures와 수정/기각 |
| API/Contract | OpenAPI, JSON Schema, event fixture |
| Safety Report | permission, denied writes, kill switch, PII scan |
| Demo Video | 3~5분 scripted E2E |
| Screenshots | dashboard, evidence drawer, replan diff, trace |
| Repro Guide | one-command seed/start/test |

실험 결과가 기대보다 나쁘면 숨기지 않고 기술을 기각한 판단 능력으로 설명한다.

## 10. 로컬 실행 규칙

목표 개발자 경험:

```text
copy .env.example .env
start dependencies
seed demo tenant
start api/worker/web
run demo scenarios
run evaluation smoke
```

실제 명령은 구현된 stack에 맞춰 최상위 README에 기록한다. 기본 실행은 외부 Provider와 실제 Large LLM 없이 deterministic fixture로 가능해야 한다. 별도 opt-in flag가 있을 때만 budget-limited model evaluation을 실행한다.

## 11. 데모 관측성

- scenario별 trace timeline
- route/model/prompt/index version
- source evidence/as_of
- token/cost/latency/cache hit
- safety decision/provider call count
- aggregate metric에는 개인/실제 business dimension 없음

로그 다운로드는 sanitized JSON만 허용한다.

## 12. 면접·발표 흐름

1. 30초: 실제 운영 Pain Point와 Safety constraint
2. 45초: Event-driven + AI Backend architecture
3. 90초: 예약주문 또는 재고 Scenario live
4. 60초: RAG/QLoRA/Router comparison과 decision
5. 30초: Agent failure recovery/HITL
6. 30초: 데모/실제 운영환경 분리와 21일 이후 추진계획

핵심 질문에 대비한다.

- 왜 Graph가 필요한/불필요한가?
- 왜 이 QLoRA checkpoint를 선택했는가?
- RAG 개선이 실제로 유의미한가?
- LLM 없이 처리되는 Event 비율은?
- 중복/timeout/잘못된 SKU에서 어떻게 피해를 막는가?
- 공개 Demo가 실제 데이터와 어떻게 분리되는가?

## 13. 실제 사업 시범운영 인계

21일 후에는 공개 Demo 배포와 실제 Pilot을 분리한다.

1. private release tag와 migration backup
2. business owner/technical owner 지정
3. G1 Read Gate와 runbook
4. alert/on-call/contact와 kill switch drill
5. Shadow metric dashboard
6. issue/feedback triage
7. G3 승격은 별도 승인 문서와 rollback drill 후

## 14. 공개 전 확인표

- [ ] 공개 repo/이미지/영상/로그에 실제 PII·매출·사업자 identifier 없음
- [ ] Demo DB/secret/queue/storage가 Production과 분리
- [ ] `WRITE_MODE=disabled`, Global Write Kill ON
- [ ] 6개 Demo Scenario clean run
- [ ] Safety denial provider call 0
- [ ] Experiment 수치가 재현 가능하고 Pending을 성과로 표기하지 않음
- [ ] License/attribution/SBOM 기록
- [ ] API/Schema/README와 배포 commit 일치
- [ ] Known limitations와 rejected techniques 공개
